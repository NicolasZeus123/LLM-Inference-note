# 解码推进与候选验证

这篇按 解码策略 → 投机解码 → 原生 MTP 的顺序，把三份 notebook 里的概念重新组织成从单步到多步的一条线。每个概念先说清楚它是什么，再说它在整个流程里起什么作用。

---

## 第一部分：单步解码与采样

这一部分要解决的问题是：模型输出一个分数向量之后，怎么把它变成一个实际的 token。

### 1.1 Logits：模型的原始打分

模型预测下一个 token 时并不直接输出 token，而是给词表里每个 token 打一个分。这个未归一化的分数叫 logits。词表 32000 个 token，模型就输出一个长度 32000 的向量，数值越大表示模型越偏向那个 token。

### 1.2 Softmax：把分数变成概率

logits 相加不等于 1，也可能是负数。Softmax 对每个 logit 取指数，再除以所有指数之和，得到总和为 1 的概率分布。

- Softmax 不改变排序：原来分数高的，概率也高
- Softmax 只是把分数之间的差距映射成概率之间的差距

所以 logits 是原始打分，softmax 把它变成可以直接采样的概率表。

### 1.3 贪心解码：永远选最高分

有了概率分布，最直接的做法是每一步取概率最高的 token，这叫贪心解码（greedy decoding）。

- 优点：完全确定，同样输入永远得到同样输出，速度快
- 缺点：容易陷入重复循环，内容单调

贪心解码是后面所有策略的基线。

### 1.4 采样解码：按概率“抽奖”

为了打破单调，可以按概率分布随机抽取下一个 token，而不是永远取最高分。概率高的 token 被抽中的机会大，低概率的也有机会，这就是采样解码（sampling decoding）。

- 优点：有随机性、有多样性
- 风险：词表里有很多概率极低但没有意义的 token，放任它们被抽中，输出就会跑偏

所以采样之前要对分布做调整、对候选做限制，温度和 Top-K / Top-p 就是干这件事的。

### 1.5 温度（Temperature）：调节分布的“尖锐程度”

温度 $T$ 是在 softmax 之前对 logits 做缩放的参数：`scaled_logits = logits / T`。

- $T < 1$（低温）：logits 差距被放大，分布更尖锐，模型更倾向高分 token，输出更保守、更确定
- $T = 1$：不改变原始分布
- $T > 1$（高温）：logits 差距被缩小，分布更平坦，低概率 token 机会变大，输出更随机，也更容易胡说

温度只改变分布形状，不改变 token 之间的排序。另外低温不完全等于贪心，采样路径上仍可能以极小概率选到非最高分的 token。

### 1.6 Top-K 采样：只留“前 K 名”

只保留概率最高的 K 个 token，把第 K 名之后的概率强制置 0，再在剩下 K 个里重新归一化并采样。

- 优点：直接砍掉长尾里的无用 token
- 缺点：K 是固定数字，但不同上下文下分布陡峭程度差别很大。分布尖锐时 K=50 可能保留太多不相关 token；分布平坦时 K=50 又可能砍掉太多合理候选。固定的 K 无法自适应

实现上有个易错点：如果第 K 名和第 K+1 名分数相同，同分的候选要一起保留。

### 1.7 Top-p（核采样）：动态保留“够用”的词

按概率从高到低累加，直到累计概率刚刚达到或超过阈值 p，把这个最小集合保留下来，后面的全部丢弃。

举例：排序后概率是 `[0.5, 0.3, 0.1, 0.05, 0.05]`，设 $p=0.85$。累加过程是 $0.5 \to 0.8 \to 0.9$，前三个 token 累计到 0.9，首次超过 0.85，所以前三个构成候选集合。

之所以叫“动态”，是因为保留的 token 数量不固定：分布尖锐时累计很快达标，保留得少；分布平坦时要累加很多才达标，保留得多。Top-p 就这样自动适应了分布的陡峭程度，比固定 K 灵活。

这里最重要的易错点是：首次达到阈值的那个边界 token 必须保留，不能因为“已经超过”就丢掉。实现时通常用掩码右移一位的技巧，保证边界 token 不被误删。

### 1.8 组合顺序

notebook 采用的顺序是：

1. **温度缩放**：调整尖锐程度
2. **Top-K 过滤**：固定排名范围
3. **Top-p 过滤**：动态累计边界
4. **Softmax 重新归一化**：让保留候选的概率总和为 1
5. **采样**（`do_sample=False` 时退化为 argmax 贪心）

顺序会影响结果，先调温度还是先截断，候选集合可能不一样。

## 第二部分：精确验证语义

这一部分要解决的问题是：说一个候选 token 被接受时，到底在比较什么，不同策略的验证标准是否一致。

### 2.1 为什么需要“验证”这个概念

贪心和采样都是单步决策：模型给分布，选一个 token，结束。后面要讲的投机解码和 MTP 都是多步策略：先一次性提出多个候选，再回头确认这些候选对不对。确认的标准就是验证语义。

验证语义要回答两件事：

1. 拿什么和什么比（比较对象）
2. 比到什么程度算通过（通过条件）

### 2.2 概率一致性验证（投机解码的语义）

投机解码的验证在概率层面进行：

- 草稿模型给出候选 token $x$ 的概率 $q(x)$
- 目标模型给出同一个 token 的概率 $p(x)$
- 接受概率 $\alpha(x) = \min(1, p(x)/q(x))$

分两种情况看：

- $p \ge q$，即目标模型不比草稿模型更不看好这个 token，$\alpha = 1$，百分之百接受
- $p < q$，即草稿模型过度自信，$\alpha = p/q < 1$，按比例降低接受概率

然后从 0 到 1 均匀抽一个数，小于 $\alpha$ 就接受，否则拒绝。

边界情况要单独处理：$q=0$ 且 $p>0$ 时接受概率设为 1，即草稿完全没考虑但目标认为可能；$q=0$ 且 $p=0$ 时接受概率为 0。

拒绝之后要修正。一旦某个候选被拒，本轮立即停止，从残差分布中重新采样一个修正 token：

$$\text{residual}(x) = \frac{\max(p(x)-q(x),\,0)}{\sum_y \max(p(y)-q(y),\,0)}$$

只保留“目标比草稿更看好”的正差值部分，归一化后采样。数学上，接受路径加上残差修正路径，合起来的输出分布恰好等于目标分布 $p$，这就是无损的理论依据。

### 2.3 贪心首选词匹配（原生 MTP 的验证语义）

原生 MTP 走贪心路径，验证方式直接得多：

- 对候选块里第 i 个 token，拿它和目标模型在该位置得分最高的 token（首选词）比较
- 相同就接受，继续检查下一个
- 不同就立即停止，后面的候选全部作废，也就是关闭后缀

这里不涉及概率比值，也不涉及随机抽样，就是确定性的“首选词是否一致”。

### 2.4 两种验证语义的对比

| 维度 | 投机解码 | 原生 MTP（贪心路径） |
|---|---|---|
| **比较对象** | 草稿概率 $q$ vs 目标概率 $p$ | 候选词 vs 目标首选词 |
| **通过条件** | 随机数 < $\min(1, p/q)$ | 确定性地“相等” |
| **拒绝后** | 从残差分布采样修正 Token | 用目标模型在该位置的首选词做修正 |
| **理论保证** | 输出分布 = 目标分布（无损） | 输出路径由目标首选词决定，质量不受候选猜测影响 |

验证不是笼统地说对不对，而是要先明确比较什么（概率还是首选词）、怎么算通过（随机接受还是确定性匹配）。两种语义分别服务于两种多步策略。

## 第三部分：MTP / EAGLE / 并行草稿候选

这一部分要解决的问题是：多步策略里的候选 token 从哪里来。典型来源有三种：独立草稿模型、特征级草稿、模型内置预测头。

### 3.1 投机解码：独立草稿模型

结构上是一个目标模型（大、慢、质量高）加一个草稿模型（小、快、质量低）。

流程：

1. 草稿模型串行生成 K 个候选 token（它也是自回归的，只能一个一个来）
2. 目标模型对这 K 个位置加上 1 个额外位置一次性批量验证
3. 按 2.2 的概率语义逐个接受或拒绝
4. 拒绝了就从残差分布修正；全部接受就从额外位置采样一个追加 token（bonus token）

优点是输出无损，草稿模型可以独立选择、独立训练。缺点是要额外部署和维护一个小模型，两个模型还得分词器对齐，协调成本不低。

### 3.2 EAGLE：特征级草稿（并行草稿候选的一种代表）

EAGLE 的完整细节不在给定的三份 notebook 里，但它是“并行草稿候选”这一类的典型代表，这里只讲核心思想，用作第三部分分类的参照。

投机解码的草稿模型是在 token 层面自回归的，要一个词一个词地生成候选，模型虽小但仍然是串行。EAGLE 的改进是在特征层面做自回归，并让草稿过程尽量并行。

核心思路：

- 草稿不再另跑一个小语言模型，而是复用目标模型内部的隐藏特征
- 在这些特征上接一个轻量预测头，并行预测未来多个位置的候选
- 因为复用了目标模型的特征，草稿质量比独立小模型高，接受率也更高

相当于把“另起炉灶跑小模型”换成“站在目标模型的中间结果上做轻量预测”，既省了独立模型，也提高了候选质量。

### 3.3 原生 MTP：模型内置的多个预测深度

结构上不额外养草稿模型，而是在目标大模型内部挂载多个预测模块，也就是多个预测深度。

- 第 1 个预测深度猜下一个 token（位置 1）
- 第 2 个预测深度猜下下个 token（位置 2）
- 第 3 个预测深度猜再下一个（位置 3），依此类推

每个深度复用主模型当前已算好的上下文状态，各自给出对相应未来位置的打分。这些深度并行工作，不需要像草稿模型那样串行生成。

每个深度选出自己的最高分 token，按位置顺序排成有序候选块。比如深度 1 选“今天”、深度 2 选“天气”、深度 3 选“很”，候选块就是 `["今天", "天气", "很"]`。

候选块长度受预算限制，也就是 `max_candidates` 参数，可以只取前 2 个深度，也可以全取。

### 3.4 三种候选来源的对比

| 维度 | 投机解码 | EAGLE | 原生 MTP |
|---|---|---|---|
| **候选来源** | 独立草稿模型 | 目标模型特征 + 轻量预测头 | 目标模型内置多个预测深度 |
| **是否需要额外模型** | 需要 | 需要轻量头（但复用特征） | 不需要，内置在检查点里 |
| **草稿是否串行** | 串行生成 K 个 | 尽量并行 | 并行 |
| **验证语义** | 概率比值 + 残差修正 | 通常也是概率/贪心验证 | 贪心首选词匹配 |
| **主要优势** | 无损、灵活 | 候选质量高、接受率高 | 无额外模型、部署简单 |

三种方案解决的是同一个问题：候选 token 从哪里来。投机解码靠外部小模型，EAGLE 靠复用目标模型特征做并行预测，原生 MTP 靠模型内部的多个预测头。来源不同，后面都要过验证这一步。

## 第四部分：动态候选预算

这一部分要解决的问题是：一轮到底该尝试推进几个 token，固定数字好还是动态调整好。

### 4.1 固定候选长度的局限

投机解码里 K 是固定数字（比如 5），原生 MTP 里 `max_candidates` 也是固定上限。但不同上下文下候选的可靠程度差别很大：

- 有些位置模型非常确定，候选几乎必对，多试几个很划算
- 有些位置模型很犹豫，第一个候选都可能错，多试就是浪费计算

固定 K 无法根据实际情况调整，这跟第一部分 Top-K 的局限是同一个道理。

### 4.2 动态预算的两种体现

第一种是 Top-p 式的动态候选数量，第一部分已经讲过。Top-p 不固定保留几个 token，而是按累计概率动态决定，分布尖锐时保留少，平坦时保留多。这是动态预算在单步采样层面的体现。

第二种是连续接受长度，这是原生 MTP 的核心观察量。这里有两个容易混的量：

| 观察量 | 含义 | 不能从它推出什么 |
|---|---|---|
| **候选长度** | 这一轮**最多尝试**了几个位置 | 不等于实际推进量——尝试 5 个可能只推进 1 个 |
| **连续接受长度** | 从第一个位置开始**连续匹配**的候选数量 | 不等于端到端加速比——还要看计算和验证开销 |

真正决定这一轮批量提交几个 token 的是连续接受长度。候选长度是伸出去的手，连续接受长度是实际抓到的东西。

### 4.3 两条收尾路径与预算的关系

- **中途不匹配（修正路径）**：连续接受了 i 个，第 i+1 个不匹配，输出为已接受的 i 个加上目标模型在第 i+1 个位置的首选词，也就是修正 token。后面的候选全部丢弃。
- **全部匹配（追加路径）**：K 个候选全通过，输出为全部 K 个加上从额外第 K+1 个目标位置采样的追加 token（bonus）。

这里有个关键点：追加 token 必须从额外的第 K+1 行目标分布中采样，不能复用最后一个候选位置的验证分布。

### 4.4 动态预算的直觉总结

动态预算的核心是不预先固定“尝试几个”，而让分布形状和验证结果决定“实际推进几个”。Top-p 用累计概率决定单步候选数量，连续接受长度用验证结果决定多步批量提交数量，两者都不是拍脑袋定一个 K。

## 第五部分：真实模型净收益复测

这一部分要解决的问题是：理论上能加速，实际跑起来是否真的更快，快了多少，怎么衡量。

### 5.1 为什么“理论加速”不等于“真实净收益”

投机解码和 MTP 的理论收益是：目标模型用 1 次前向最多推进 K+1 个 token（全部接受时）。真实净收益还要扣掉下面几项成本：

1. **候选生成成本**：草稿模型要跑 K 次前向，虽然模型小，但不是零；MTP 的预测深度也要计算
2. **验证成本**：目标模型只跑 1 次，但这次是批量验证 K+1 个位置，比单点前向略贵
3. **协调开销**：两个模型之间的数据传输、分词器对齐、采样逻辑
4. **接受率的不确定性**：草稿猜不准时连续接受长度很短，推进量接近 1，加速比接近 1 甚至更差，因为多付了草稿成本

理论加速比对应的是最好情况，真实净收益要把候选计算和验证成本一起算进去。

### 5.2 衡量净收益的关键指标

| 指标 | 含义 | 注意点 |
|---|---|---|
| **连续接受长度** | 每轮实际批量提交的候选数 | 不等于加速比 |
| **每轮输出长度** | 接受前缀 + 修正词/追加词 | 同样要结合成本看 |
| **目标模型前向次数** | 生成固定长度文本需要跑多少次目标模型 | 这是加速的直接来源 |
| **端到端延迟 / 吞吐** | 实际墙钟时间或每秒 Token 数 | **最终指标**，包含所有开销 |
| **接受率** | 候选被接受的比例 | 接受率越高，净收益越大 |

### 5.3 复测时要注意的坑

1. 不能只看候选长度。候选长度是尝试范围，连续接受长度才是实际推进量。
2. 不能只看连续接受长度。它不等于端到端加速比，还要看候选计算和验证本身的开销。
3. 要区分无损和有损。投机解码在概率语义下输出分布不变，是无损的；MTP 贪心路径下输出由目标首选词决定，质量不受候选猜测影响，但两者验证语义不同，不能混着说。
4. 要在真实模型上测。小模型和大模型的接受率可能差很多，理论分析和 toy 实验代替不了真实复测。

### 5.4 一条完整的净收益判断链

> 候选来源（草稿模型 / EAGLE / MTP 预测头）→ 验证语义（概率比值 / 贪心匹配）→ 连续接受长度（实际推进量）→ 扣除候选与验证成本 → 端到端延迟/吞吐（真实净收益）

这四步走完，才能判断一个加速方案在真实模型上划不划算。

## 全链路总结：一张表串起五个部分

| 部分 | 核心问题 | 关键概念 | 一句话结论 |
|---|---|---|---|
| **① 单步解码与采样** | 分数怎么变成词？ | Logits、Softmax、贪心、采样、温度、Top-K、Top-p | 温度调形状，Top-K 固定截断，Top-p 动态截断，边界词必须保留 |
| **② 精确验证语义** | “接受”到底在比什么？ | 概率比值 $\min(1,p/q)$、残差分布、贪心首选词匹配 | 投机解码比概率、MTP 比首选词，两种语义不能混用 |
| **③ MTP / EAGLE / 并行草稿候选** | 候选词从哪里来？ | 独立草稿模型、特征级草稿、内置预测深度、有序候选块 | 外部小模型 → 复用特征 → 内置预测头，部署越来越轻 |
| **④ 动态候选预算** | 一轮尝试推进几个？ | Top-p 动态数量、候选长度 vs 连续接受长度、修正/追加路径 | 让分布形状和验证结果决定推进量，不拍脑袋定 K |
| **⑤ 真实模型净收益复测** | 真的快了吗？ | 接受率、连续接受长度、前向次数、端到端延迟/吞吐 | 理论加速 ≠ 净收益，必须扣除候选与验证成本后在真实模型上测 |

从单步怎么选 token，到多步怎么验证候选，再到候选从哪来、预算怎么定，最后落到真实收益怎么测，每一步都是前一步的延伸。
